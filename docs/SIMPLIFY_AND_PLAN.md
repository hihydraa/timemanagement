### A1. Navigation 3 แท็บ

โครงใหม่ (เดสก์ท็อป = top nav, มือถือ = bottom tab bar พร้อมปุ่ม FAB ตรงกลาง):

| แท็บ                 | เนื้อหา                                                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| **วันนี้** (หน้าแรก) | Insight bar, การ์ด "ทำต่อไป", Top 3, timeline วันนี้, ส่วน **"ยังไม่จัดเวลา"** (แทนหน้า Inbox), เดดไลน์/เลยกำหนด, ปุ่ม "จัดวันให้ที" |
| **แผน**              | ปฏิทิน (สัปดาห์แบบการ์ดต่อวัน / time grid / เดือน / รายการ), ถาดงานที่ยังไม่มีเวลา, Load bar รายวัน                                  |
| **ฉัน**              | Dobby, สรุปสัปดาห์ (Review), สถิติ/Insights, ตั้งค่า (เวลาทำงาน, เชื่อม LINE/Google, ประเภทงาน, โหมด UI, export)                     |

การย้ายฟีเจอร์เดิม:

- **Inbox** → ส่วน "ยังไม่จัดเวลา" ในหน้าวันนี้ + ถาดงานในหน้าแผน (ใช้ query เดิม ไม่ต้องสร้างตารางใหม่)
- **Focus Timer** → ปุ่ม "โฟกัส" บนการ์ดงานและการ์ด "ทำต่อไป" เปิดเป็น **มินิไทเมอร์ลอย** (ไม่ใช่หน้าเต็ม) เก็บ route `/focus` ไว้เปิดจากปุ่มนั้นได้ แต่ไม่อยู่ในเมนู
- **Matrix** → ซ่อนในโหมดง่าย / ในโหมดเต็มเป็นตัวสลับมุมมองในหน้า "แผน"
- **Review** → การ์ดสรุปในหน้า "วันนี้" ช่วงวันศุกร์ 15:00 ถึงวันอาทิตย์ (ปิดได้) และเป็นส่วนหนึ่งของแท็บ "ฉัน"
- **Stats** → ส่วนหนึ่งของแท็บ "ฉัน"

**Redirect:** route เก่า (`/inbox`, `/matrix`, `/focus`, `/review`, `/stats`) ต้อง redirect ไปที่ใหม่ ไม่ให้ลิงก์/บุ๊กมาร์กเดิมพัง (เช่น `/inbox` → `/today#unscheduled`, `/review` และ `/stats` → `/me`)

**AC:**

- เมนูมี 3 รายการเท่านั้นทั้งเดสก์ท็อปและมือถือ (375px ใช้ bottom tab bar ได้ ไม่มี horizontal scroll)
- route เก่าทุกตัว redirect ถูกต้อง มี test
- ฟีเจอร์ที่ย้ายยังทำงานได้ครบ (ลบ/แก้/ติ๊กเสร็จจาก "ยังไม่จัดเวลา" ได้เหมือนหน้า Inbox เดิม)

### A2. เพิ่มงานด้วยช่องพิมพ์เดียว

- **Quick Add Bar** อยู่ด้านบนของหน้า "วันนี้" ตลอดเวลา (มือถือ: ติดล่างเหนือ tab bar หรือเปิดจาก FAB) shortcut `n` และ `/` บนเดสก์ท็อป
- พิมพ์ชื่อ + **Enter = บันทึกทันที** ใช้ค่าเริ่มต้นทั้งหมดที่ไม่ได้ระบุ (ดู A3)
- ใช้ **parser ภาษาไทยตัวเดียวกับ LINE** (`src/services/parser.ts` import ใช้ร่วม ห้ามเขียนซ้ำ) เช่น "ส่งรายงาน พรุ่งนี้ 14:00 สำคัญ"
- ระหว่างพิมพ์แสดง **ชิปพรีวิว** ใต้ช่อง (วัน, เวลา, สำคัญ, ประเภท, เวลาประมาณ) กดชิปเพื่อแก้ได้ก่อน Enter
- หลังบันทึก: งานปรากฏในรายการทันที (optimistic UI) พร้อมชิปที่กดแก้ในบรรทัดได้ และ **Undo toast** 5 วินาที
- ไม่ระบุวัน → ค่าเริ่มต้นคือ **"วันนี้, ไม่กำหนดเวลา"** ถ้าผู้ใช้พิมพ์คำที่บ่งว่าไม่เร่ง ("วันหลัง", "สักวัน") → ไป "ยังไม่จัดเวลา"
- ปุ่ม "+ งานใหม่" เดิมยังอยู่ แต่เปิดฟอร์มแบบเต็ม (ตัวเลือกเพิ่มเติม) สำหรับคนที่ต้องการ
- ฟอร์มเต็ม: แสดงเฉพาะ **ชื่อ, วัน/เวลา, สำคัญ, เวลาประมาณ** เป็นค่าเริ่มต้น ที่เหลือซ่อนหลังปุ่ม "ตัวเลือกเพิ่มเติม" (รายละเอียด, ประเภท, แท็ก, ทำซ้ำ, subtask, ไฟล์แนบ, แจ้งเตือนล่วงหน้า, สวิตช์ sync Google)

**AC:**

- เพิ่มงานได้ด้วยการพิมพ์ 1 ประโยค + Enter ไม่เกิน 1 ขั้นตอน (วัดจากเปิดหน้า → งานขึ้นรายการ)
- พิมพ์ "ส่งรายงาน พรุ่งนี้ 14:00 สำคัญ" แล้วชิปแสดงวัน/เวลา/สำคัญถูกต้องก่อนบันทึก และบันทึกตรงกับพรีวิว
- Undo ภายใน 5 วินาทีลบงานที่เพิ่งสร้างได้ (และลบ event ใน Google ถ้า sync ไปแล้ว)
- มี test ว่า Quick Add และ LINE ใช้ฟังก์ชัน parser ตัวเดียวกัน

### A3. ลดจำนวนฟิลด์ที่ผู้ใช้ต้องตัดสินใจ

| ฟิลด์                                     | การเปลี่ยนแปลง                                                                                                             |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **ความเร่งด่วน**                          | **คำนวณอัตโนมัติ ผู้ใช้ไม่ต้องตั้ง** จากวันที่เกี่ยวข้อง = `due_at ?? due_date ?? start_at` (ดูกติกาด้านล่าง)              |
| **ความสำคัญ**                             | เหลือ **ปุ่มเดียว "⭐ สำคัญ"** (ติ๊ก/ไม่ติ๊ก)                                                                              |
| **ประเภทงาน**                             | ไม่บังคับ เดาจากคำในชื่อ (ตารางคำสำคัญตั้งค่าได้) แล้วถ้าไม่เจอใช้ประเภทที่ใช้ล่าสุด หรือ "ไม่มีประเภท"                    |
| **เวลาประมาณ**                            | ชิปเลือกเร็ว 15 น. / 30 น. / 1 ชม. / 2 ชม. ค่าเริ่มต้น **30 นาที** (บันทึกจริงในฟิลด์เพื่อให้คำนวณภาระงานได้ ไม่ปล่อยว่าง) |
| แท็ก, ทำซ้ำ, subtask, ไฟล์แนบ, รายละเอียด | ซ่อนใน "ตัวเลือกเพิ่มเติม"                                                                                                 |

**กติกาคำนวณความเร่งด่วน** (ฟังก์ชันบริสุทธิ์ `computeUrgency(task, now)` ใน `src/lib/urgency.ts` ใช้ได้ทั้ง web และ worker):

```
ref = due_at ?? due_date ?? start_at ?? null   // เทียบเป็นวันที่ใน Asia/Bangkok
ref == null                         → 1
ref < วันนี้ (เลยกำหนด) หรือ = วันนี้ → 4
ref = พรุ่งนี้                       → 3
ref ภายใน 3 วัน                      → 2
อื่น ๆ                               → 1
```

- เก็บคอลัมน์ `urgency` เดิมไว้ใน DB (ไม่ลบ) แต่ **ไม่ให้ UI แก้ไขอีก** และไม่ใช้เป็นแหล่งความจริง ให้คำนวณตอนอ่านทุกครั้ง (สีแถบซ้าย, คะแนน, Matrix, Insight)
- **ความสำคัญ:** ปุ่ม "⭐ สำคัญ" เมื่อเปิด = เขียน `importance = 4` ปิด = `importance = 2` ข้อมูลเดิมที่ `importance >= 3` ถือว่า "สำคัญ" เพื่อไม่ทำให้ข้อมูลเก่าเปลี่ยนความหมาย **ไม่ต้อง migrate ข้อมูลเดิม**
- LINE parser: คงรองรับ `!ด่วน`/`!u1..!u4` เพื่อความเข้ากันได้แต่ **ตีความเป็นการตั้งเดดไลน์วันนี้** (ถ้ายังไม่มีวัน) แทนการตั้งค่าเร่งด่วนตรง ๆ และ `!สำคัญ` = ติ๊กสำคัญ
- Matrix (โหมดเต็ม): แกน "ด่วน" อิงค่าที่คำนวณ ลากการ์ดไปช่อง "ด่วน/ไม่ด่วน" จะเสนอ **ปรับเดดไลน์** แทนการตั้ง urgency ตรง ๆ (ถ้างานไม่มีเดดไลน์ ให้ถามวันที่)

**AC:**

- `computeUrgency` มี unit test ครอบคลุม: ไม่มีวัน, เลยกำหนด, วันนี้, พรุ่งนี้, 3 วัน, 4+ วัน, งาน all-day, ข้ามเที่ยงคืน Asia/Bangkok (freeze เวลา)
- ไม่มีตัวเลือก "ความเร่งด่วน" เหลือในฟอร์มใด ๆ
- สีแถบซ้าย/ชิปนับถอยหลัง/คะแนนจัดอันดับ ใช้ค่าที่คำนวณทั้งหมด (ค้นแล้วไม่มีโค้ดอ่าน `task.urgency` ตรง ๆ ใน UI)
- ข้อมูลงานเดิมแสดงผลถูกต้องหลังอัปเกรด

### A4. Undo toast แทนกล่องยืนยัน

- การกระทำที่ย้อนกลับได้ง่าย (ลบงานเดี่ยว, เสร็จ, เลื่อน, ย้ายวัน, ใช้แผน "จัดวันให้ที") → ทำทันที + toast "…แล้ว · เลิกทำ" ค้าง 5–8 วินาที
- ลบถาวรหลายรายการ/ลบประเภท/ตัดการเชื่อมต่อ Google → ยังคงใช้กล่องยืนยัน
- การเลิกทำต้องย้อนผลข้างเคียงด้วย (event ใน Google, reminder ที่ตั้งไว้) ใช้ soft-delete 10 วินาที (`deleted_at`) แล้วค่อยลบจริงด้วย cron เดิม

**AC:** ลบงาน → เลิกทำ → งานกลับมาครบ (ไฟล์แนบ, event Google, reminder) มี test

### A5. โหมดง่าย / โหมดเต็ม

- เพิ่ม `user_settings.ui_mode` ค่า `'simple' | 'full'` **ค่าเริ่มต้น `simple`** สลับได้ที่ "ฉัน → ตั้งค่า"
- **โหมดง่ายซ่อน:** Matrix, ปุ่มย้อมสีตาม (ใช้ "ตามประเภท" ตายตัว), sidebar ตัวกรองละเอียด (เหลือช่องค้นหา + ชิปประเภท), แท็ก, subtask, recurrence UI ละเอียด (เหลือแค่ "ทำซ้ำ: ทุกวัน/ทุกสัปดาห์/ทุกเดือน" แบบเลือกหนึ่งอย่าง)
- **โหมดเต็มเปิดทั้งหมด** ตามที่เคยทำไว้
- ฟีเจอร์ที่ซ่อนต้อง **ไม่ถูกลบ** และข้อมูลที่สร้างจากโหมดเต็ม (แท็ก, subtask) ยังแสดงอ่านอย่างเดียวในโหมดง่าย

**AC:** สลับโหมดแล้ว UI เปลี่ยนทันทีโดยไม่รีโหลด ข้อมูลไม่หาย มี test ว่าโหมดง่ายไม่เรนเดอร์ส่วนที่ซ่อน

### A6. Onboarding 3 ข้อ

แสดงครั้งแรกหลัง login (ข้ามได้ ทำทีหลังได้ใน "ฉัน"):

1. **เวลาทำงานของคุณ** — เริ่ม/เลิก และวันทำงาน (ค่าเริ่มต้น 09:00–18:00, จันทร์–ศุกร์) → `work_start`, `work_end`, `work_days`
2. **เชื่อม Google Calendar** — เพื่อให้รู้ว่าว่างกี่ชั่วโมง (ปุ่มเชื่อม/ข้าม)
3. **รับแจ้งเตือนทางไหน** — LINE / แจ้งเตือนในเว็บ (แสดงขั้นตอนผูก LINE ถ้าเลือก)
   จบด้วยการเด้งให้ **จดงานแรก** ผ่าน Quick Add ทันที

**AC:** ผู้ใช้ใหม่เดินจากสมัครถึงจดงานแรกได้ภายใน 1 นาที (ทดสอบด้วยมือ) และข้ามทุกข้อได้โดยระบบยังใช้ค่าเริ่มต้นได้

### A7. วัดผลแบบไม่ละเมิดความเป็นส่วนตัว

### B1. ดึงนัดจาก Google Calendar (อ่านอย่างเดียว)

**Scope & การเชื่อมต่อ**

- ปัจจุบันใช้ scope `calendar.events` (อ่าน/เขียนเหตุการณ์) ซึ่งเรียก `events.list` ได้ ถ้าต้องการให้ผู้ใช้เลือกปฏิทินหลายอัน (`calendarList.list`) ให้ขอ scope เพิ่ม `calendar.calendarlist.readonly` แบบ incremental consent ถ้า token เดิมไม่มี scope นี้ ให้ขอ consent ใหม่ **ไม่บังคับผู้ใช้เดิมทุกคน** (ค่าเริ่มต้นใช้ปฏิทิน `primary` ไปก่อน)
- เก็บค่า `user_settings.gcal_pull_enabled` (ค่าเริ่มต้น 1 เมื่อเชื่อมต่อ) และ `gcal_calendars_selected` (JSON array ของ calendar id, ค่าเริ่มต้น `["primary"]`)

**ตารางใหม่ `external_events`**

```
id (pk), user_id, source ('google'), calendar_id, external_id,
title, start_at (UTC ISO หรือ null ถ้า all_day), end_at,
all_day int, start_date, end_date (กรณี all_day, end เป็น exclusive ตาม Google),
is_busy int,            -- 0 ถ้า transparency = 'transparent'
event_type text,        -- 'default' | 'outOfOffice' | 'focusTime' | 'workingLocation' ฯลฯ
html_link, status, etag, updated_at
UNIQUE(user_id, source, calendar_id, external_id)
INDEX(user_id, start_at), INDEX(user_id, start_date)
sync_state(user_id, calendar_id, sync_token, last_synced_at)
```

- **ไม่เก็บ** description, attendees, หรือข้อมูลที่ไม่จำเป็น (เก็บแค่ที่ใช้แสดงผลและคำนวณ)
- ล้างแถวที่จบไปแล้วเกิน 30 วันด้วย cron เดิม และ **ลบทั้งหมดทันทีเมื่อผู้ใช้ตัดการเชื่อมต่อ Google**

**กลยุทธ์ซิงก์**

- ใช้ `events.list` พร้อม `singleEvents=true`, `orderBy=startTime`, ช่วง **วันนี้−7 วัน ถึง +60 วัน** และ **syncToken** สำหรับ incremental (ถ้า API ตอบ 410 ให้ล้างแล้วดึงใหม่ทั้งช่วง)
- เรียกซิงก์เมื่อ (ก) เปิดหน้า "วันนี้"/"แผน" และข้อมูลเก่ากว่า 5 นาที (ข) cron ทุก 15 นาทีสำหรับผู้ใช้ที่เชื่อมต่ออยู่ (ต้องไม่เกินโควตา Workers ฟรี: ทำเป็นชุดเล็ก ๆ และจำกัดจำนวนผู้ใช้ต่อรอบ)
- ถ้า API ตอบ 401 → refresh token (ตามที่ทำไว้), 429/403 rate limit → exponential backoff + เก็บสถานะ "ซิงก์ไม่สำเร็จ" แสดงแถบเล็ก ๆ ในเว็บ ไม่ทำให้หน้าพัง
- ถ้า refresh token ใช้ไม่ได้ ให้แจ้งผู้ใช้ให้เชื่อมต่อใหม่ (ไม่ลบข้อมูลเดิมทันที)

**กติกาการนับเป็น "เวลาไม่ว่าง"**

| เหตุการณ์                                                       | นับเป็นไม่ว่าง?                                            |
| --------------------------------------------------------------- | ---------------------------------------------------------- |
| นัดปกติ (`transparency` ไม่ใช่ `transparent`)                   | ใช่                                                        |
| `transparent` (แสดงว่า "ว่าง")                                  | ไม่                                                        |
| ที่ผู้ใช้ตอบ **ไม่เข้าร่วม** (self `responseStatus = declined`) | ไม่                                                        |
| `status = cancelled`                                            | ไม่                                                        |
| all-day (เช่น วันหยุด/วันเกิด)                                  | **ไม่** เป็นค่าเริ่มต้น (ตั้งค่า `all_day_blocks` = 1 ได้) |

| `eventType = focusTime`                                         | ใช่ (ถือว่าจองเวลาแล้ว)                                    |

**การแสดงผล**

- นัดจาก Google แสดงเป็น **บล็อกสีเทา อ่านอย่างเดียว** (พื้นเทาอ่อน + ไอคอนปฏิทิน) ใน timeline หน้า "วันนี้", ตารางเวลา/การ์ดสัปดาห์ในหน้า "แผน" แยกชัดจากงานของ Dobby

- ปุ่มแสดง/ซ่อนชั้น "นัดจาก Google" ในหน้า "แผน"

### B2. คำนวณเวลาว่างจริง (`src/lib/availability.ts`)

ฟังก์ชันบริสุทธิ์ (pure) ไม่เรียก DB/เวลาปัจจุบันตรง ๆ รับ `now` เป็นพารามิเตอร์:

```
computeFreeSlots({
  date,                 // วันที่ใน Asia/Bangkok
  workStart, workEnd,   // เช่น "09:00","18:00"
  workDays,             // เช่น [1,2,3,4,5]
  busy: Interval[],     // จากนัด is_busy + งานที่ล็อกเวลาแล้ว
  now,                  // ถ้า date = วันนี้ เริ่มจาก max(now, workStart) ปัดขึ้นเป็นช่วง 15 นาที
  minSlotMinutes = 15,
  bufferMinutes = 5     // เว้นระยะหลังนัด
}) → { slots: Interval[], availableMinutes: number }
```

- รวมช่วงที่ทับกันก่อนหัก, ตัดให้อยู่ในหน้าต่างเวลาทำงาน, ตัดช่วงที่สั้นกว่า `minSlotMinutes`
- วันที่ไม่ใช่วันทำงาน → `availableMinutes = 0` (แต่ผู้ใช้ยังจัดงานลงได้ด้วยตัวเอง Load bar แสดง "วันหยุด")
- วันที่มี `outOfOffice` → ไม่มีช่วงว่าง
- **Load bar** (จาก `UX_REVISION.md` 5.3) ต้องเปลี่ยนมาใช้ `availableMinutes` จากฟังก์ชันนี้ แทนค่าคงที่
- ระวัง DST/เขตเวลา: Asia/Bangkok ไม่มี DST แต่ฟังก์ชันต้องไม่ผูกกับ offset ตายตัวนอก `src/lib/time.ts`

**AC (unit test ≥ 15 เคส, freeze เวลา):** ไม่มีนัด, นัดกลางวัน, นัดทับกัน, นัดคาบเกี่ยวนอกเวลาทำงาน, นัดชนต้น/ท้ายหน้าต่าง, วันนี้ที่เลยเวลาเริ่มทำงานแล้ว, วันนี้เลยเวลาเลิกงานแล้ว, วันหยุด, outOfOffice, ช่วงว่างสั้นกว่า 15 นาที, buffer, งานที่ล็อกเวลาแล้วนับเป็น busy

### B3. "จัดวันให้ที" (Auto-plan)

**หลักการ:** ระบบ **เสนอ** ผู้ใช้ **ยืนยัน** ห้ามบันทึกอัตโนมัติ

**อินพุต:** วันเป้าหมาย (วันนี้/พรุ่งนี้)
**งานที่เข้าข่าย:** ยังไม่เสร็จ และ (กำหนดไว้ในวันนั้น หรือ เดดไลน์วันนั้น หรือ เลยกำหนด หรือ อยู่ใน Top 3 ของวันนั้น หรือ อยู่ในส่วน "ยังไม่จัดเวลา" และเดดไลน์ภายใน 3 วัน) และ **ยังไม่มีเวลาเริ่มตายตัว**
**งานที่มีเวลาเริ่มตายตัวอยู่แล้ว** (ผู้ใช้ตั้ง `start_at` เอง) ถือเป็น busy ไม่ย้าย

**อัลกอริทึม (`src/lib/autoplan.ts`, pure function):**

1. คำนวณ `freeSlots` ด้วย B2
2. คำนวณคะแนนของแต่ละงานด้วยฟังก์ชันคะแนนเดิม (`UX_REVISION.md` 5.5) โดยให้ `urgency` มาจาก `computeUrgency` (A3) และ `importance` ตาม A3
3. เรียงตามคะแนนมากไปน้อย (คะแนนเท่ากัน เรียงตามเดดไลน์ก่อน แล้วตามเวลาที่สร้าง เพื่อให้ผลคงที่ ทำซ้ำแล้วได้เหมือนเดิม)
4. วางแบบ greedy: งานที่ "สำคัญ" ให้ลองวางใน **ช่วงทำงานลึก** `PEAK = 09:00–12:00` ก่อน (ค่าคงที่ใน config ยังไม่ทำ UI) งานอื่นวางที่ช่วงว่างแรกที่ยัดได้ ความยาว = `estimate_minutes` (ถ้า null ใช้ 30 นาที และแสดงหมายเหตุ)
5. **ไม่แบ่งงานเป็นหลายบล็อกในเวอร์ชันนี้** ถ้าไม่มีช่วงว่างที่ใหญ่พอ → ไป `unplaced` ด้วยเหตุผล `no_slot`
6. วางเพิ่มจนเต็มเวลาว่าง ไม่เกินหน้าต่างเวลาทำงาน ไม่ทับนัด/งานที่ล็อกเวลา
7. ใส่ `bufferMinutes` ระหว่างบล็อกตามค่าตั้งต้น

**เอาต์พุต:**

```
{
  placements: [{ taskId, startAt, endAt, usedDefaultEstimate: boolean }],
  unplaced:   [{ taskId, reason: 'no_slot' | 'past_work_hours' | 'day_off' }],
  summary:    { plannedMinutes, availableMinutes, load, overbooked: boolean }
}
```

- ต้อง **deterministic** (input เดียวกัน = output เดียวกัน)

**API:**

- `POST /api/plan/preview` body `{ date }` → คืนแผนตามข้างบน **ไม่เขียน DB**
- `POST /api/plan/apply` body `{ date, placements: [{taskId,startAt,endAt}] }` →
  - เซิร์ฟเวอร์ **ตรวจซ้ำ** ทุกบล็อก (ไม่ทับ busy ปัจจุบัน, อยู่ในหน้าต่างเวลาทำงาน, งานยังเป็นของผู้ใช้และยังไม่เสร็จ) ถ้าตรวจไม่ผ่านตอบ **409** พร้อมแผนใหม่ที่คำนวณสด (กรณีปฏิทินเปลี่ยนระหว่างที่ผู้ใช้ดูพรีวิว)
  - เขียน `start_at/end_at` ของทุกงานในธุรกรรมเดียว (all-or-nothing) แล้วคืน **snapshot ค่าก่อนหน้า** สำหรับเลิกทำ
  - ถ้าเปิด `gcal_sync_enabled` ให้ซิงก์ไป Google ตามปกติ (ใส่ `dobbyTaskId`)
- `POST /api/plan/undo` body `{ snapshot }` → คืนค่าก่อนหน้า (และอัปเดต/ลบ event ใน Google ที่เพิ่งสร้าง) ใช้ได้ภายใน 10 นาทีหลัง apply
- ทุก endpoint กรองด้วย `user_id` และ validate ด้วย zod

**UI ("จัดวันให้ที"):**

- ปุ่มเด่นในหน้า "วันนี้" (แสดงเมื่อมีงานที่เข้าข่าย ≥ 1) และในหัวคอลัมน์วันของหน้า "แผน" มีตัวเลือกวัน (วันนี้ / พรุ่งนี้)
- เปิด **bottom sheet / modal พรีวิว:** timeline ของวันนั้น นัดจาก Google สีเทา บล็อกที่เสนอเป็นเส้นประสีแบรนด์ มีข้อความสรุป "จัด 5 งาน รวม 3 ชม. จากเวลาว่าง 4 ชม."
- รายการ **"ไม่ได้จัด"** แยกชัด พร้อมเหตุผลภาษาคน ("ไม่มีช่วงว่างยาวพอ", "เลยเวลาทำงานแล้ว") และปุ่มเสนอ "เลื่อนไปพรุ่งนี้"
- ผู้ใช้ **เอาบล็อกออกจากแผนได้ (✕)** แล้วแผนคำนวณใหม่เฉพาะส่วนที่เหลือโดยไม่เอางานนั้นกลับมา (ลาก/ปรับเวลาบล็อกด้วยมือไม่ต้องทำในรอบนี้ ถ้าจะทำให้ทำแบบเรียบง่าย)
- ปุ่ม **"ใช้แผนนี้"** / **"ยกเลิก"** หลังใช้แผน แสดง toast "จัดแล้ว N งาน · เลิกทำ"
- งานที่ไม่มี estimate ใช้ 30 นาที ให้แสดงไอคอนเล็ก ๆ ว่า "ใช้ค่าประมาณ 30 นาที" กดเพื่อปรับ

**AC:**

- พรีวิวไม่เขียนข้อมูลใด ๆ (ตรวจด้วย test ว่า DB ไม่เปลี่ยน)
- แผนไม่ทับนัด Google, ไม่ทับงานที่ล็อกเวลา, ไม่เกินเวลาทำงาน, ไม่ย้ายงานที่เสร็จแล้ว
- ผลเหมือนเดิมเมื่อเรียกซ้ำด้วยข้อมูลเดิม (deterministic)
- `apply` ซ้อนกับนัดที่เพิ่งเข้ามาได้ 409 และ UI แสดงแผนใหม่ ไม่บันทึกครึ่ง ๆ กลาง ๆ
- เลิกทำคืนค่าเดิมครบทุกงาน และ event ใน Google สอดคล้อง
- unit test ของ `autoplan` ≥ 15 เคส: ไม่มีเวลาว่าง, เวลาว่างพอดี, งานใหญ่เกินช่องว่าง, งานสำคัญได้ช่วงเช้า, คะแนนเท่ากัน, งานไม่มี estimate, วันหยุด, วันนี้ที่ผ่านมาครึ่งวัน, งานเสร็จแล้วไม่ถูกจัด, งานที่ล็อกเวลาไม่ถูกย้าย

### B4. นัดใหม่ทับงาน (Conflict)

- หลังซิงก์ทุกครั้ง ตรวจว่ามี **งานที่มีเวลาเริ่ม-จบ** ทับกับนัด is_busy ใหม่หรือไม่
- แสดงชิป **"ชนกับนัด"** บนงานนั้น (หน้า "วันนี้" และ "แผน") และการ์ดสรุปในหน้า "วันนี้": "งาน 2 รายการชนกับนัดใหม่" พร้อมปุ่ม **"จัดใหม่"**
- "จัดใหม่" เรียก auto-plan **เฉพาะงานที่ชน** (นำงานเหล่านั้นออกจากเวลาเดิมก่อน แล้ววางใหม่ในช่วงว่างที่เหลือ) ผ่านพรีวิวและการยืนยันตามปกติ
- **ห้าม** ย้ายงานเองโดยไม่ถาม
- ไม่ต้องส่งแจ้งเตือน LINE เรื่องนี้ในรอบนี้ (ประหยัดโควตา push)

**AC:** สร้างนัดใหม่ใน Google ที่ทับงาน → ซิงก์แล้วขึ้นชิปเตือน → "จัดใหม่" เสนอเวลาใหม่ที่ไม่ชน → ยืนยันแล้วชิปหาย (test ด้วย mock Google API)

### B5. เชื่อมกับ Insight bar และ Next up

- Insight bar บนหน้า "วันนี้" ใช้ `availableMinutes` จริง เช่น "วันนี้ว่าง 3 ชม. 30 นาที มีงาน 5 งาน (ประมาณ 2 ชม.)" หรือ "วันนี้ว่างเหลือ 1 ชม. แต่มีงาน 4 ชม. ลองให้ฉันจัดใหม่ไหม" (ปุ่มลัดไป "จัดวันให้ที")
- การ์ด "ทำต่อไป" ต้องแจ้งนัดที่จะเริ่มภายใน 30 นาที ("อีก 20 นาทีมีนัด …")
- ถ้ายังไม่เชื่อม Google แสดงข้อความชวนเชื่อม ("ให้ฉันรู้นัดของคุณ จะจัดวันได้แม่นขึ้น") และใช้เวลาทำงานล้วน ๆ คำนวณไปก่อน

**AC:** ข้อความ Insight เปลี่ยนตามสถานการณ์จริง (ทดสอบ: ไม่เชื่อม Google, ว่างมาก, ว่างน้อย, วันหยุด, วันที่มี outOfOffice)

```
POST /api/plan/preview            POST /api/plan/apply            POST /api/plan/undo
```

## 5. สิ่งที่ห้ามทำ

- ห้ามบันทึกแผน "จัดวันให้ที" โดยไม่ผ่านพรีวิวและการยืนยันของผู้ใช้
- ห้ามแก้ไข/ลบนัดที่ผู้ใช้สร้างเองใน Google Calendar (ดึงมาอ่านอย่างเดียว) แอปแก้ได้เฉพาะ event ที่ Dobby สร้าง (มี `dobbyTaskId`)
- ห้ามเก็บรายละเอียดนัด (description/attendees) หรือเนื้อหางานใน `usage_events`
- ห้ามลบคอลัมน์/ฟีเจอร์เดิม (urgency, Matrix, Focus, Review, Stats) ให้ซ่อน/ย้ายเท่านั้น
- ห้ามเพิ่ม dependency หนัก (ต้องรันบน Cloudflare Workers ฟรี) ถ้าจำเป็น ให้เลือกตัวเล็กและบันทึกเหตุผลใน `docs/DECISIONS.md`
- ห้ามยิง LINE push เพิ่มจากฟีเจอร์รอบนี้
- ห้ามใช้สีเป็นสัญญาณเดียว (นัดสีเทา/ชนกับนัด/เลยกำหนด ต้องมีไอคอนหรือข้อความประกอบเสมอ)
- ถ้า spec ข้อใดไม่ชัดหรือขัดกับโค้ดที่มี ให้เลือกทางที่เรียบง่ายและเข้ากับโครงสร้างเดิม บันทึกใน `docs/DECISIONS.md` แล้วทำต่อ ไม่ต้องหยุดถาม ยกเว้นเรื่องที่ย้อนกลับไม่ได้ (ลบข้อมูล production, เปลี่ยน schema ที่มีข้อมูลจริงแบบทำลายข้อมูล)

## 7. ชุดทดสอบที่ต้องมี (สรุป)

- `computeUrgency` (A3) — เทสต์ตามตารางเงื่อนไข
- `parser` ใช้ร่วม Quick Add/LINE — เทสต์ว่า import ไฟล์เดียวกัน

- Redirect ของ route เก่า (A1), soft-delete + undo (A4), `usage_events` ไม่มีข้อความอิสระ (A7)
- ทุกการทดสอบเวลา freeze `now` ที่ Asia/Bangkok

## 8. ลำดับการทำงาน (commit แยกต่อ Step)

### Step 1 — Navigation 3 แท็บ + redirect (A1)

**AC:** ตาม A1 เมนู 3 รายการ, route เก่า redirect, ฟีเจอร์ที่ย้ายยังทำงานครบ

### Step 2 — Quick Add + ลดฟิลด์ + Undo toast (A2, A3, A4)

**AC:** ตาม A2–A4 เพิ่มงานด้วย 1 ประโยค + Enter, urgency คำนวณเอง ไม่มีตัวเลือกให้ตั้ง, undo ครบผลข้างเคียง

### Step 3 — โหมดง่าย/เต็ม + Onboarding + วัดผล (A5, A6, A7)

**AC:** ตาม A5–A7 ผู้ใช้ใหม่จดงานแรกได้ภายใน 1 นาที, สลับโหมดไม่เสียข้อมูล, เหตุการณ์ถูกเก็บไม่ซ้ำและไม่มีเนื้อหางาน

### Step 4 — ดึงนัด Google + เวลาว่างจริง (B1, B2)

**AC:** ตาม B1–B2 นัดแสดงถูกต้อง กฎ busy ถูกต้อง ไม่ซ้ำกับงานที่ซิงก์ออก Load bar ใช้เวลาว่างจริง

### Step 5 — จัดวันให้ที (B3)

**AC:** ตาม B3 พรีวิวไม่เขียน DB, แผนไม่ทับนัด, deterministic, apply ตรวจซ้ำ + undo

### Step 6 — Conflict + Insight + QA รวม (B4, B5)

**AC:** ตาม B4–B5 และรันการตรวจรวม:

- Lighthouse mobile ≥ 90 (Performance/Accessibility) ที่ 375px / 768px / 1280px
- ทดสอบด้วยมือหนึ่งรอบเต็ม: สมัคร → onboarding → เชื่อม Google → จดงาน 5 งานด้วย Quick Add → "จัดวันให้ที" → ใช้แผน → สร้างนัดใหม่ใน Google ที่ชน → จัดใหม่ → เลิกทำ
- อัปเดต `README.md` และ `docs/SETUP.md` ให้ตรงกับพฤติกรรมใหม่

## 9. Definition of Done (ภาพรวม)

1. เมนูมี 3 แท็บ และผู้ใช้ใหม่เข้าใจโดยไม่ต้องอธิบาย
2. จดงานได้ด้วยการพิมพ์ 1 ประโยค + Enter และไม่ต้องตัดสินใจเรื่องความเร่งด่วนเอง
3. เชื่อม Google Calendar แล้วเห็นนัดสีเทาในวันนี้/แผน และรู้ว่า **วันนี้ว่างกี่ชั่วโมงจริง**
4. กดปุ่ม **"จัดวันให้ที"** เห็นพรีวิว ยืนยัน และเลิกทำได้ โดยแผนไม่ทับนัดและไม่เกินเวลาทำงาน
5. นัดใหม่ที่ชนกับงานถูกเตือน และจัดใหม่ได้ด้วยการกดครั้งเดียว
6. ทุกอย่างรันบน Cloudflare free tier ได้เหมือนเดิม ไม่เพิ่มการใช้ LINE push
