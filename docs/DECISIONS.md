| #   | เรื่อง                      | การตัดสินใจ                                                                  | เหตุผล                                                      |

| 1   | ชื่อโปรเจกต์                | **Dobby** (spec เดิมใช้ชื่อ TimeFlow)                                        | ผู้ใช้กำหนด                                                 |
| 2   | Cron                        | ใช้ `*/5 * * * *` ตัวเดียว (ตามข้อแนะนำหัวข้อ 8) และเช็คเวลา digest ในโค้ด   | ตั้งเวลาละเอียดได้โดยไม่แก้ cron, ไม่ซ้ำซ้อนกับ `0 * * * *` |

| 6   | Routing assets              | `run_worker_first` เฉพาะ `/api/*`, `/auth/*`, `/webhook/*`; ที่เหลือเป็น SPA | ให้ asset ฟรีไม่นับ request ของ Worker                      |
| 7   | Timezone                    | คำนวณด้วย offset คงที่ +7 ใน `src/lib/time.ts`                               | ไทยไม่มี DST, ไม่พึ่ง tz ของ runtime                        |

| 16  | Mini calendar           | Phase 1 ใช้ช่อง "ไปยังวันที่" (date picker) แทน mini calendar เต็มรูปแบบ                                           | ไม่กระทบ AC; เก็บไว้ทำใน Polish                                                                    |

## Phase 2

| #   | เรื่อง                    | การตัดสินใจ                                                                                                                                             | เหตุผล                                                                  |
| --- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 20  | ชนิดไฟล์ที่รองรับ         | นามสกุล `pdf png jpg jpeg gif webp docx xlsx pptx txt csv zip` (ไม่รองรับ svg/html/doc/xls เก่า)                                                        | svg/html รัน script ได้ (XSS); ตามรายการใน spec 5.4                     |
| 21  | วิธีตัดสิน MIME           | ใช้ **นามสกุล** กำหนด MIME แล้วตรวจ **magic bytes** ให้ตรง; ไม่เชื่อ `Content-Type` ที่ client ส่งมา                                                    | ค่าจาก client ปลอมได้ง่าย                                               |
| 22  | จำกัดการอัปโหลด           | ไฟล์ละ ≤ `MAX_UPLOAD_MB`, ครั้งละ ≤ 5 ไฟล์, ต้องมี `Content-Length` และไม่เกิน 5×max+1MB, quota รวมต่อผู้ใช้ = `USER_STORAGE_QUOTA_MB`                  | กัน memory เต็มใน Worker (formData ถูก buffer) และกันใช้พื้นที่เกิน     |
| 23  | อัปโหลดแบบ all-or-nothing | ตรวจทุกไฟล์ก่อนเขียน R2; ถ้าเขียนกลางทางล้มเหลวจะย้อนกลับไฟล์ที่เขียนไปแล้ว                                                                             | ไม่เหลือไฟล์กำพร้า                                                      |
| 24  | R2 key                    | `{userId}/{taskId}/{uuid}` ไม่ใช้ชื่อไฟล์ผู้ใช้; ชื่อเดิมเก็บใน DB หลัง sanitize (ตัดพาธ/อักขระควบคุม/จุดนำหน้า/จำกัด 120 ตัว)                          | กัน path traversal และ header injection                                 |
| 25  | การดาวน์โหลด              | ผ่าน `/api/attachments/:id` เท่านั้น ตรวจ owner; รูป = `inline`, อื่น ๆ = `attachment`; ส่ง `nosniff` + `CSP: sandbox`; ข้าม CSP global เฉพาะ route นี้ | R2 ไม่เป็น public; ไฟล์ที่เปิดดูรัน script ไม่ได้                       |
| 26  | ลำดับการลบ                | ลบ R2 **ก่อน** แล้วค่อยลบแถว DB (ทั้งลบไฟล์เดี่ยวและลบงาน)                                                                                              | ถ้า R2 ล้มเหลว แถวยังอยู่ ผู้ใช้ลองใหม่ได้ ไม่เกิดไฟล์กำพร้าที่หาไม่เจอ |
| 27  | งานใหม่ + ไฟล์            | เลือกไฟล์ได้ตั้งแต่ตอนสร้าง แล้วอัปโหลดหลังสร้างงานสำเร็จ; ถ้าแนบพลาดงานยังถูกสร้างและแจ้งเตือนผู้ใช้                                                   | ไม่ทำให้ข้อมูลที่กรอกไว้หาย                                             |
| 28  | ไม่รองรับ (ยัง)           | resumable/chunked upload, Range request, virus scan                                                                                                     | เกินขอบเขต free tier / MVP                                              |

## Phase 3

| #   | เรื่อง                         | การตัดสินใจ                                                                                                                                                                                                | เหตุผล                                                                                 |
| --- | ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 29  | `!p1..!p4`                     | `!pN` = importance N ตรง ๆ (4 = สำคัญสุด) เหมือน `!uN` = urgency N                                                                                                                                         | spec ไม่บอกทิศทาง; ใช้ค่าเดียวกับฟิลด์ในระบบเพื่อไม่สับสน                              |
| 30  | เวลาแบบไทย                     | ระบบ 6 ชั่วโมง: `2 โมงเช้า`=08:00, `4 โมงเย็น`=16:00, `บ่าย 2`=14:00, `4 ทุ่ม`=22:00, `6 ทุ่ม`=00:00; `N โมง` เปล่า ๆ: 1–5 = บ่าย (13–17), 6–11 = เช้า                                                     | ตรงตัวอย่างใน spec และการพูดจริงส่วนใหญ่                                               |
| 31  | วันในสัปดาห์                   | `วันจันทร์` = จันทร์ที่จะถึง (ถ้าวันนี้เป็นจันทร์ = วันนี้); `หน้า` = สัปดาห์ปฏิทินถัดไป (จันทร์–อาทิตย์); `อาทิตย์หน้า` (ไม่มีคำว่า "วัน") = สัปดาห์หน้า → จันทร์ถัดไป ส่วน `วันอาทิตย์หน้า` = วันอาทิตย์ | "อาทิตย์" คลุมเครือ (วัน/สัปดาห์)                                                      |
| 32  | วัน/เวลาที่ผ่านมาแล้ว          | ไม่เดา ไม่สร้างงาน แต่ถามกลับด้วย Quick Reply (message action) ที่ส่ง **ข้อความที่เขียนใหม่แล้ว** (เช่น "… พรุ่งนี้ 09:00", "… 3 พ.ย. 2570") กลับมาเป็นข้อความของผู้ใช้ และมี `!ok` สำหรับ "บันทึกตามเดิม" | ไม่ต้องเก็บ state รอยืนยัน; ใช้ parser ตัวเดิมประมวลผลต่อ; ข้ามการถามเมื่อเป็นงานทำซ้ำ |
| 33  | `#ประเภท` ที่ไม่พบ             | เก็บเป็นแท็กแทน (ไม่ทิ้ง)                                                                                                                                                                                  | ไม่ให้ข้อมูลที่ผู้ใช้พิมพ์หาย                                                          |
| 34  | เดดไลน์                        | มีเวลา → `due_at` (ไม่มี start แสดงเป็นบล็อก ⏰); มีแต่วัน → งาน all-day ในวันนั้น; มีทั้ง start และเดดไลน์ → เก็บทั้งคู่; คำบอกเดดไลน์ต้องอยู่ติดหน้าวัน/เวลา (กัน "ก่อนนอน" ใน title)                    | ตามชุดคำใน spec                                                                        |
| 35  | อ้างอิงงานใน `เสร็จ/ลบ/เลื่อน` | เลข = ลำดับในรายการล่าสุดที่บอทแสดง (เก็บใน `line_state` ต่อ LINE user); ชื่อ = ตรงทั้งชื่อก่อน แล้วค่อยบางส่วน เฉพาะงานที่ยังไม่เสร็จ; ถ้าตรงหลายงานจะแสดงรายการให้เลือกด้วยเลข ไม่เดา                    | กันทำผิดงาน                                                                            |
| 36  | `เลื่อน <ชื่อ> <เมื่อไหร่>`    | แยกชื่อกับวัน/เวลาโดยลองตัดคำท้ายที่เป็นวัน/เวลาล้วน ๆ และชื่อที่เหลือต้องตรงงานจริง (รองรับชื่องานที่มีคำว่า "พรุ่งนี้/ศุกร์" อยู่ในชื่อ)                                                                 | พบจากการทดสอบ                                                                          |
| 37  | กันเดารหัสผูกบัญชี             | ผิดครบ 5 ครั้งใน 10 นาที (ต่อ LINE user) ล็อก 10 นาที; รหัสใช้ได้ครั้งเดียว, 10 นาที, ขอใหม่แล้วรหัสเก่าใช้ไม่ได้                                                                                          | รหัส 6 หลัก เดาได้ถ้าไม่จำกัด                                                          |
| 38  | กัน event ซ้ำ                  | ตาราง `line_events` (PK = `webhookEventId`) เก็บ 7 วัน แล้วล้าง                                                                                                                                            | ครอบคลุมช่วงที่ LINE redeliver                                                         |
| 39  | รูป/ไฟล์จาก LINE               | แนบกับงานที่สร้างผ่าน LINE ล่าสุดภายใน 10 นาที; ไม่งั้นถามด้วย Quick Reply (4 งานล่าสุดที่ยังไม่เสร็จ) โดยเก็บไฟล์ที่รอไว้ 30 นาทีใน `line_state`; ใช้กติกา/โควตาเดียวกับเว็บ (`saveUploads`)              | ตาม 6.4; ความปลอดภัยเท่ากัน                                                            |
| 40  | ขอบเขตของแชท                   | รองรับเฉพาะแชทส่วนตัว; เมิน group/room, sticker, วิดีโอ, เสียง และ `unfollow`                                                                                                                              | MVP                                                                                    |
| 41  | ไม่ใช้ push                    | Phase 3 ตอบด้วย reply token ทั้งหมด (ไม่เสีย quota)                                                                                                                                                        | push เป็นของ Phase 5                                                                   |
| 42  | งานทำซ้ำ                       | parser/LINE เก็บ `recurrence_rule` ได้แล้ว แต่ปฏิทินเว็บ **ยังไม่ขยายเป็นหลายครั้ง** (Phase 6)                                                                                                             | ตามลำดับ Phase                                                                         |
| 43  | Workers AI fallback            | ยังไม่ทำ (เป็นทางเลือกใน spec); parser คืนค่า `confidence` ไว้ให้ต่อยอด                                                                                                                                    | ลดความซับซ้อนและการพึ่งโควตา                                                           |
