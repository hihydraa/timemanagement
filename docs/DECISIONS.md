## S&P Step 2 — ฟอร์มง่าย, Quick Add, Undo

150. **ฟอร์มงาน**: วัน (ค่าเริ่มต้น = วันนี้) + เวลาเริ่ม 24 ชม. (select ชั่วโมง/นาที) + ระยะเวลา (ชิป 15/30/60/120) แทน "เวลาสิ้นสุด/ประมาณการ"; เดดไลน์เป็นบล็อกเสริม. ไม่มี `datetime-local` (ปัญหา mm/dd/yyyy AM/PM). Map: ไม่ใส่เวลา → all-day; มีเวลา → startAt/endAt; มีแต่เดดไลน์ → dueAt.
151. **ความเร่งด่วนคำนวณที่เซิร์ฟเวอร์** (`computeUrgency`: เดดไลน์/วันที่ ≤ วันนี้ → 4, พรุ่งนี้ → 3, ≤3 วัน → 2, อื่น ๆ → 1) ใน DTO; คอลัมน์ `urgency` ยังอยู่แต่ไม่ใช่ source of truth; UI ไม่มีช่องกรอก. LINE `!ด่วน/!u3/!u4` ที่ไม่มีวัน → เดดไลน์วันนี้.
152. **ความสำคัญ** = ปุ่ม ⭐ (importance 4 / 2); parser รับคำว่า "สำคัญ/⭐" ท้าย/หน้าข้อความ.
153. **Quick Add** ใช้ `src/services/parser.ts` ตัวเดียวกับ LINE (web import ตรง — pure function); มีชิปพรีวิวแก้ได้, optimistic, คีย์ลัด `n` และ `/`.
154. **Undo — เบี่ยงจากสเปก (`deleted_at`)**: ไม่ทำ soft-delete เพราะต้องแก้ ~31 จุดอ่าน + R2/GCal; ใช้ **สร้างกลับจาก snapshot** (`lib/undo.ts`) เฉพาะงานที่ไม่มีไฟล์แนบ/subtask/ซีรีส์ — งานที่มีไฟล์ใช้กล่องยืนยันเดิม (ไฟล์ใน R2 ลบแล้วกู้ไม่ได้). เสร็จ/เลื่อน/Quick Add เลิกทำด้วย inverse patch. ข้อจำกัด: id งานใหม่หลังเลิกลบ.
155. **Matrix**: ลากข้ามแกนความเร่งด่วน = เสนอเดดไลน์ใหม่ (ฝั่งด่วน → วันนี้, ไม่ด่วน → +5 วัน) แทนการตั้ง urgency; แกนสำคัญปรับ importance ตรง ๆ.

## S&P Step 3 — โหมดง่าย/เต็ม, Onboarding, วัดผล

156. **ผู้ใช้เดิม = โหมดเต็ม + ถือว่าผ่าน onboarding** (migration 0008 อัปเดตแถวเดิม) เพื่อไม่ให้ฟีเจอร์ที่ใช้อยู่หายทันที; ผู้ใช้ใหม่ได้ค่าเริ่มต้น `simple` ตามสเปค (สร้างแถว settings ให้ผู้ใช้ที่ยังไม่มีแถวด้วย).
157. **โหมดง่ายซ่อนอย่างเดียว ไม่ลบ**: ไม่มี Matrix (ถ้าค้างอยู่จะแสดงการ์ดสัปดาห์), ย้อมสีตามประเภทตายตัว, ตัวกรองเหลือค้นหา + ประเภท, ไม่มีช่องแท็ก/subtask, ทำซ้ำเหลือ "ไม่ทำซ้ำ/ทุกวัน/สัปดาห์/เดือน". ข้อมูลจากโหมดเต็มแสดงอ่านอย่างเดียว (แท็ก, subtask, กฎทำซ้ำซับซ้อน) และ **บันทึกในโหมดง่ายไม่แตะค่าเหล่านั้น** (ไม่ส่ง `recurrenceRule` เมื่อกฎซับซ้อน).
158. **สลับโหมดทันที**: state ใน AppShell + แคช `localStorage` ต่อบัญชี (กันกระพริบ) แล้ว sync เซิร์ฟเวอร์ ไม่รีโหลดหน้า. ตรวจด้วย e2e (Playwright) เพราะโปรเจกต์ไม่มี jsdom — ข้อ "test ว่าโหมดง่ายไม่เรนเดอร์ส่วนที่ซ่อน" ทำเป็น e2e แทน unit.
159. **Onboarding 3 ข้อ** (เวลาทำงาน → Google → LINE/เว็บ) ข้ามได้ทุกข้อ; "ข้ามทั้งหมด" ใช้ค่าเริ่มต้น; จบแล้วโฟกัส Quick Add ทันที; ทำซ้ำได้จาก "ฉัน". ข้อ "เว็บเท่านั้น" = `lineNotifyEnabled=false`. กลับจากการเชื่อม Google จะไปต่อข้อ 3 (จำขั้นใน sessionStorage).
160. **usage_events**: allowlist ชื่อเหตุการณ์ + `sanitizeProps` (ตัวเลข/boolean/สตริง `[a-z0-9_]{1,24}` เท่านั้น); `signup/first_task_created/gcal_connected` ครั้งเดียวต่อผู้ใช้, `morning_plan_opened` วันละครั้ง (นับการเปิดหน้า "วันนี้" ครั้งแรกของวัน — ยังไม่แยกช่วงเช้า); หน้าเว็บส่งได้เฉพาะ `morning_plan_opened` (ไม่รับ props); opt-out = ไม่เก็บและ **ลบของเดิมทันที**; ลบบัญชีลบ usage_events ด้วย. `auto_plan_*` จะเพิ่มใน Step 5.
