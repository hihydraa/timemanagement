## 1. ปัญหาที่ต้องแก้ (สรุป)

1. หน้า Calendar เหมือน Google Calendar เกินไป ไม่มีจุดเด่นของ "ระบบบริหารเวลา"
   → หน้าปัจจุบันตอบได้แค่ "มีอะไรในตาราง" แต่ควรตอบว่า **"ตอนนี้ควรทำอะไร" และ "วันนี้/สัปดาห์นี้ทำไหวไหม"**
2. Design / UX-UI ยังไม่สวยและไม่สม่ำเสมอ
3. มีบั๊กและความสับสนด้านข้อมูลที่เห็นจากหน้าจอจริง (หัวข้อ 6)

หลักการออกแบบ: **งาน ≠ นัด** (งานมีเวลาประมาณ มีเดดไลน์ ย้ายได้ / นัดคือเวลาตายตัว), **เห็นภาระงานก่อนตัดสินใจ**, **โทนอบอุ่นเป็นมิตร มี Dobby เป็นผู้ช่วย**

## 2. Design Tokens (ใช้ CSS variables / Tailwind theme เดียวทั้งแอป)

ปรับค่าตามโทนที่มีอยู่แล้ว (พื้นครีม + เขียวเข้ม) ให้เป็นระบบ:

```css
:root {
  /* พื้นหลัง/พื้นผิว */
  --bg: #faf7ef; /* พื้นหน้าเว็บ (ครีม) */
  --surface: #ffffff; /* การ์ด */
  --surface-2: #f3eedf; /* พื้นรอง, hover, วันนี้ */
  --border: #e6dfcb;

  /* ตัวอักษร */
  --text: #23302a;
  --text-muted: #6b7568;

  /* แบรนด์ (เขียว Dobby) */
  --brand: #3f6650;
  --brand-strong: #2c4a39;
  --brand-soft: #e4eee7;

  /* ความเร่งด่วน (แถบซ้าย / ชิป) */
  --urg-4: #d9534f; /* ด่วนมาก */
  --urg-3: #e8803f; /* ด่วน */
  --urg-2: #e9be3c; /* ปกติ */
  --urg-1: #a9aeb8; /* ไม่ด่วน */

  /* สถานะภาระงาน */
  --load-ok: #5fa777;
  --load-warn: #e9be3c;
  --load-over: #d9534f;

  /* รัศมี/เงา/ระยะ */
  --radius-sm: 8px;
  --radius-md: 12px;
  --radius-lg: 16px;
  --shadow-sm: 0 1px 2px rgba(35, 48, 42, 0.06);
  --shadow-md: 0 4px 14px rgba(35, 48, 42, 0.08);
  --space: 4px; /* ใช้ทวีคูณ 4 ทั้งระบบ: 4/8/12/16/24/32 */
}
:root[data-theme='dark'] {
  /* กำหนดชุดสี dark ให้ครบ ทุก token ข้างบน */
}
```

**สีของประเภทงาน (category):** ใช้พาสเทลโทนเดียวกัน — พื้น event อ่อน (ความสว่าง ~90%) + ตัวอักษรสีเข้มของ hue เดียวกัน + จุดสีเต็มที่ชื่อประเภท **ห้ามใช้สีฟ้าเริ่มต้นของ FullCalendar** (ตอนนี้ event ทุกอันเป็นฟ้าจัดซึ่งหลุดจากแบรนด์)
ต้องผ่าน contrast WCAG AA ระหว่างตัวอักษรกับพื้น event

**ฟอนต์:** `Noto Sans Thai` หรือ `IBM Plex Sans Thai` (เลือกอย่างใดอย่างหนึ่ง โหลดผ่าน Google Fonts หรือ self-host) น้ำหนัก 400/500/600, `line-height: 1.6` สำหรับข้อความ, 1.35 สำหรับหัวข้อ (กันสระ/วรรณยุกต์ไทยถูกตัด)
ขนาด: 12 / 14 (body) / 16 / 20 / 24 / 32

**Layout กลาง:** สร้าง component `<PageContainer>` ที่ `max-width: 1200px; margin: 0 auto; padding: 0 16px` (มือถือ) / `0 24px` (เดสก์ท็อป) ใช้ครอบ **ทุกหน้า** (Today, Calendar, Inbox, Matrix, Review, Stats)

## 3. ระบบสัญลักษณ์งาน (Visual Language)

แยกหน้าที่ของแต่ละสัญญาณ ไม่ให้ซ้อนกันจนอ่านไม่ออก:

| สัญญาณ         | สื่อถึง          | รูปแบบ                                                                 |
| -------------- | ---------------- | ---------------------------------------------------------------------- |
| สีพื้น + จุดสี | **ประเภทงาน**    | พื้นพาสเทล                                                             |
| แถบซ้ายหนา 4px | **ความเร่งด่วน** | สี `--urg-*`                                                           |
| ชิปคำ          | **ความสำคัญ**    | "สำคัญมาก / สำคัญ / ปกติ / ต่ำ" (แสดงเฉพาะระดับ ≥ สำคัญ เพื่อลดความรก) |
| ชิปนับถอยหลัง  | **เวลาที่เหลือ** | "อีก 2 ชม." / "เลยมา 1 วัน" (สีแดงเมื่อเลย)                            |
| ขีดฆ่า + จาง   | **เสร็จแล้ว**    | opacity .5                                                             |

- **เลิกใช้ `!!`, `!!!`, `★★★`** ในการ์ดและ event ทั้งหมด (อ่านไม่รู้เรื่อง) ให้แทนด้วยชิปคำ/ไอคอนตามตารางข้างบน พร้อม `title`/tooltip อธิบาย
- เดดไลน์แสดงเป็น **ไอคอนธง + เวลา** ไม่ใช่บล็อกที่มีความสูง (ดูบั๊ก 6.2)
- ปุ่ม "ย้อมสีตาม: ประเภท | เร่งด่วน | สำคัญ" ที่มีอยู่แล้ว **เก็บไว้** แต่ย้ายเข้า popover "มุมมอง" และตั้งค่าเริ่มต้นเป็น "ประเภท"

## 4. โครงหน้าและ Navigation

### 4.1 Top navigation

ลำดับเมนู: **วันนี้ · ปฏิทิน · Inbox · Matrix · โฟกัส · รีวิว · สถิติ**

- เพิ่มหน้า **"วันนี้"** เป็นหน้าแรก (หัวข้อ 5.1) — เมนู "ปฏิทิน" เปลี่ยนเป็นหน้าวางแผน (5.2)
- ปุ่ม **"+ งานใหม่"** อยู่ขวาบนคงเดิม และเพิ่ม **Quick add** (5.6) ตรงกลาง/ข้างปุ่ม
- แท็บที่เลือกมี underline สีแบรนด์ + น้ำหนักตัวอักษรหนาขึ้น

### 4.2 Sidebar ซ้าย (หน้าปฏิทิน)

ปัจจุบันรกเกินไป (แผง "เลือกสิ่งที่แสดงในแถบ" เปิดค้างตลอด) ให้ปรับเป็น:

- Mini calendar (เดือน) ด้านบน
- ตัวกรองด่วน: ชิปประเภทงาน (คลิกเพื่อกรอง), ชิปความเร่งด่วน, ช่องค้นหา
- ปุ่ม **"ปรับแต่ง"** เปิด popover ที่มีรายการ checkbox "เลือกสิ่งที่แสดงในแถบ" เดิม — **ปิดเป็นค่าเริ่มต้น**
- ปุ่ม "ล้างตัวกรอง" แสดงเฉพาะตอนมีตัวกรองทำงานอยู่ พร้อมจำนวนตัวกรองที่เปิด

### 4.3 มือถือ (mobile-first, breakpoint ≤ 768px)

- **Bottom tab bar** 5 ปุ่ม: วันนี้ / ปฏิทิน / (+) / Inbox / เพิ่มเติม (Matrix, โฟกัส, รีวิว, สถิติ อยู่ใน "เพิ่มเติม")
- ปุ่ม **(+)** ตรงกลางเป็น FAB เปิด Quick add
- Sidebar กลายเป็น bottom sheet (เปิดด้วยปุ่ม "กรอง")
- ปฏิทินสัปดาห์บนมือถือแสดงเป็น **รายการเลื่อนแนวตั้งรายวัน** (agenda) + แถบเลือกวัน 7 วันด้านบน แทนตารางชั่วโมง

## 5. ฟีเจอร์ที่ทำให้ Calendar แตกต่าง

### 5.1 หน้า "วันนี้" (Today Cockpit) — ใหม่ เป็นหน้าแรก

องค์ประกอบ (บนลงล่าง):

1. **Dobby Insight Bar** — บรรทัดเดียว สร้างจากข้อมูลจริง (ไม่ใช่ข้อความตายตัว) เช่น
   - "วันนี้มี 5 งาน ใช้ราว 3 ชม. ว่างอีก 4 ชม. 👍"
   - "วันนี้แน่นไปหน่อย งานรวม 9 ชม. ลองย้ายสักงานไหม" (+ ปุ่มลัด "ดูงานที่ย้ายได้")
   - "เหลือเดดไลน์ 1 งานก่อน 17:00"
   - วันที่ไม่มีงาน: ข้อความให้กำลังใจ + ปุ่ม "เพิ่มงาน" / "ดู Inbox"
   - แสดงรูป Dobby ขนาดเล็ก (มีสถานะสีหน้า 3 แบบ: สบายๆ / ยุ่ง / ยินดี)
2. **การ์ด "ทำต่อไป" (Next up)** — 1 งานที่ระบบแนะนำให้ทำตอนนี้ (หัวข้อ 5.5) แสดงชื่อ, ประเภท, เวลาประมาณ, เวลาเหลือถึงเดดไลน์ ปุ่มหลัก **"เริ่มโฟกัส"** (เปิด Focus Timer ผูกกับงานนั้น) และปุ่มรอง "เสร็จแล้ว" / "เลื่อน"
3. **Progress ring** — วงแหวนแสดง "เสร็จ x / ทั้งหมด y" ของวันนี้ + นาทีโฟกัสสะสม
4. **งาน 3 อันดับของวัน (Top 3)** — ผู้ใช้เลือกเอง (ดาวปักหมุด) ถ้ายังไม่เลือกให้แสดงปุ่มเชิญชวน "เลือก 3 งานสำคัญวันนี้" (พิธีเช้า, หัวข้อ 5.4)
5. **Timeline วันนี้** — แนวตั้ง เรียงตามเวลา มี **เส้น "ตอนนี้"** สีแบรนด์เลื่อนตามเวลาจริง, ช่วงเวลาที่ผ่านแล้วจางลง, ช่องว่างที่ยาว ≥ 45 นาทีแสดงเป็น "ช่วงว่าง 14:00–16:30" กดเพื่อวางงานจากถาดลงไปได้
6. **ส่วน "เดดไลน์วันนี้"** และ **"เลยกำหนด"** แยกเป็นการ์ดเล็ก (เลยกำหนดมีปุ่ม "เลื่อนทั้งหมดไปวันนี้/พรุ่งนี้")

เดสก์ท็อป: 2 คอลัมน์ (ซ้าย = Insight + Next up + Top 3, ขวา = Timeline) / มือถือ: คอลัมน์เดียวตามลำดับข้างบน

### 5.2 หน้า "ปฏิทิน" — Week Planner (ไม่ใช่ตารางชั่วโมงอย่างเดียว)

- มุมมอง **สัปดาห์** เปลี่ยนค่าเริ่มต้นเป็นแบบ **การ์ดต่อวัน** (7 คอลัมน์) แต่ละคอลัมน์มี:
  - หัวคอลัมน์: ชื่อวัน + วันที่ + **แถบภาระงาน (Load bar)** (5.3) + จำนวนงาน
  - รายการงาน/นัดของวันนั้นเป็นการ์ดเรียงตามเวลา
  - ปุ่ม "+" เพิ่มงานในวันนั้น
- สลับมุมมองได้: **การ์ด (ค่าเริ่มต้น)** / **ตารางเวลา (time grid เดิม)** / เดือน / รายการ — ใช้ FullCalendar เฉพาะ time grid, เดือน, list ส่วนมุมมองการ์ดเขียนเป็น component เอง
- **ถาดงาน (Task Tray)** ด้านขวา (เดสก์ท็อป) / bottom sheet (มือถือ): แสดงงานที่ **ยังไม่มีเวลา** (จาก Inbox + งานที่มีเดดไลน์แต่ยังไม่จัดเวลา) จัดกลุ่ม "มีเดดไลน์ใกล้ / ไม่มีวันที่" ลากการ์ดไปวางที่:
  - คอลัมน์วัน (มุมมองการ์ด) → กำหนดวัน
  - ช่องเวลา (time grid) → กำหนดวัน + เวลาเริ่ม โดยความยาวบล็อกใช้ `estimate_minutes` (ไม่มีให้ใช้ 30 นาที)
- งานที่มีเดดไลน์แสดง **ธง** ที่วันเดดไลน์แม้ผู้ใช้จัดเวลาทำไว้วันอื่น (เช่นทำวันอังคาร ส่งพฤหัส → ธงที่พฤหัส)

### 5.3 แถบภาระงาน (Load Bar) — จุดขายหลัก

คำนวณต่อวัน:

```
available_minutes = (ชั่วโมงทำงานที่ตั้งค่า เช่น 09:00–18:00, ค่าเริ่มต้น 8 ชม.) − ผลรวมเวลาของ "นัด" ที่เป็นเวลาตายตัว
planned_minutes   = ผลรวม estimate_minutes ของงานที่ยังไม่เสร็จในวันนั้น (งานไม่มี estimate นับ 30 นาที)
load = planned_minutes / available_minutes
```

- ≤ 70% → เขียว (`--load-ok`), 70–100% → เหลือง, > 100% → แดง (`--load-over`)
- แสดงเป็นแถบบางใต้หัววัน + ข้อความ "3 ชม. / 7 ชม." เมื่อ hover/กด
- เมื่อวันไหนเป็นสีแดง แสดงปุ่ม **"แนะนำย้ายงาน"** → เสนอ 1–3 งานที่ย้ายได้ (คะแนนต่ำ, ไม่มีเดดไลน์วันนั้น) ไปวันที่ภาระต่ำที่สุดก่อนเดดไลน์ ผู้ใช้กดยอมรับหรือปฏิเสธทีละรายการ
- Settings: เพิ่มช่อง "ชั่วโมงทำงานต่อวัน" (เริ่ม–จบ) และ "วันทำงาน" (จ–ศ ค่าเริ่มต้น) → ใส่ใน `user_settings` (เพิ่ม migration: `work_start`, `work_end`, `work_days`)

### 5.4 พิธีเช้า / พิธีเย็น (Daily Rituals)

- **พิธีเช้า (modal/bottom sheet ครั้งแรกของวัน หรือปุ่ม "วางแผนวันนี้")**: แสดงงานวันนี้ + เลยกำหนด ให้ติ๊กเลือก **Top 3** แล้วดู Load Bar ของวัน ผู้ใช้ข้ามได้ จำค่า "ข้ามวันนี้"
- **พิธีเย็น (ปุ่ม "ปิดวัน" ในหน้าวันนี้ หลังเวลาที่ตั้ง หรือกดเอง)**: แสดงสิ่งที่ทำเสร็จ (ให้กำลังใจ) + งานที่ค้าง พร้อมตัวเลือกต่องาน: เลื่อนไปพรุ่งนี้ / เลือกวันอื่น / ลบ / ย้ายกลับ Inbox + ปุ่ม "เลื่อนทั้งหมดไปพรุ่งนี้"
- เก็บข้อมูล Top 3 ใน `tasks.is_top3_date` (nullable date) หรือตารางแยก `daily_top` — เลือกแบบที่เรียบง่ายกว่า บันทึกใน `docs/DECISIONS.md`

### 5.5 "ทำต่อไป" และปุ่ม "จัดวันให้ที" (Smart Suggestion)

คะแนนงาน (ใช้ทั้งการ์ด Next up, การเรียงถาดงาน และปุ่มจัดวัน):

```
score = urgency*2 + importance*2
      + deadlineBoost     // เลยกำหนด +8, วันนี้ +6, พรุ่งนี้ +4, ≤3 วัน +2, อื่นๆ 0
      + top3Boost         // อยู่ใน Top 3 วันนี้ +3
      − snoozePenalty     // เลื่อนมาแล้วทุกครั้ง −0.5 (ไม่ต่ำกว่า −2) เพื่อไม่ให้งานเดิมถูกดันไปเรื่อย
```

- **Next up** = งานที่ยังไม่เสร็จ คะแนนสูงสุด ที่ (ก) มีเวลาเริ่มใกล้ตอนนี้ หรือ (ข) ไม่มีเวลากำหนดและอยู่ในวันนี้/เลยกำหนด ถ้ามีนัดที่เริ่มภายใน 30 นาที ให้แจ้ง "อีก 20 นาทีมีนัด …" บนการ์ด
- **ปุ่ม "จัดวันให้ที"**: เรียงงานวันนี้ตามคะแนน แล้ววางลงช่วงว่างในชั่วโมงทำงาน (ไม่ทับนัด, เริ่มจากเวลาปัจจุบันถ้าเป็นวันนี้) ตาม `estimate_minutes` → แสดง **พรีวิวแผน** ให้ผู้ใช้กด "ใช้แผนนี้" / "แก้ไข" / "ยกเลิก" **ห้ามบันทึกอัตโนมัติ**
- ถ้างานไม่พอดีกับช่วงว่างทั้งหมด ให้แสดงกลุ่ม "ไม่พอเวลา" แยก พร้อมปุ่มแนะนำย้าย
- ใส่ unit test สำหรับฟังก์ชันคะแนนและการวางช่วงว่าง (`src/lib/planner.ts` หรือฝั่ง web ตามโครงสร้างเดิม) โดย freeze เวลา

### 5.6 Quick Add (พิมพ์เร็ว)

- ช่องพิมพ์ที่หัวเว็บ (shortcut `n` หรือ `/`) ใช้ parser ภาษาไทยตัวเดียวกับ LINE (`src/services/parser.ts` — import ใช้ร่วมกัน ห้ามเขียนซ้ำ)
- ขณะพิมพ์แสดง **พรีวิวเป็นชิป** ใต้ช่อง: วันที่, เวลา, ประเภท, ความเร่งด่วน, ความสำคัญ, ระยะเวลา แก้ชิปแต่ละอันได้ กด Enter บันทึก
- ไม่ระบุวัน → เข้า Inbox

### 5.7 Matrix: ทำ Drag & Drop จริง

- ลากการ์ดข้ามช่องเพื่อปรับ urgency/importance (ใช้ `@dnd-kit/core` หรือ HTML5 DnD ตามที่โปรเจกต์ใช้อยู่แล้ว)
- เก็บ dropdown "ย้ายไป" ไว้เป็นทางเลือกเฉพาะมือถือ/ทัชสกรีน
- การ์ดแสดงเวลาที่เหลือถึงเดดไลน์ (ชิปนับถอยหลัง) แทนสัญลักษณ์ `!!`/`★`
- ช่อง "ทำทันที" ที่มีงานเกิน 5 อัน แสดงคำเตือนเบา ๆ "ช่องนี้เยอะเกินไป ลองทบทวนความเร่งด่วนอีกครั้ง"

### 5.8 Micro-interactions และ Dobby

- ติ๊กงานเสร็จ: แอนิเมชันเช็คถูก + การ์ดจางหายแบบนุ่ม (≤ 300ms) + Dobby แสดงสีหน้ายินดี ไม่เกิน 1.5 วินาที เมื่อทำ Top 3 ครบให้แสดงฉลองเล็ก ๆ (ไม่บล็อกการใช้งาน)
- เคารพ `prefers-reduced-motion` (ปิดแอนิเมชันทั้งหมดที่ไม่จำเป็น)
- Empty state ทุกหน้าใช้ Dobby + ข้อความเป็นมิตร + ปุ่มลงมือทำ (ตามที่ Inbox และ Review ทำไว้แล้ว ให้ทุกหน้าเป็นแบบเดียวกัน)
- Loading ใช้ skeleton ไม่ใช้ spinner เปล่า, Error ใช้ข้อความบอกวิธีแก้ + ปุ่มลองใหม่

## 6. บั๊กและความสับสนที่ต้องแก้ (พบจากหน้าจอจริง)

6.1 **แกน Y กราฟหน้าสถิติ** แสดง `1, 1, 0` ซ้ำ → บังคับ tick เป็นจำนวนเต็มไม่ซ้ำ (เช่น ใช้ `Math.ceil(max)` และจำนวน tick ≤ max+1) และเมื่อข้อมูลน้อย (≤ 14 วัน มีงานเสร็จ ≤ 3 วัน) ให้เปลี่ยนเป็น **heatmap รายวันแบบปฏิทินเล็ก** แทนกราฟแท่งเดี่ยว ๆ

6.2 **งานที่ start = end** (เช่น "16:37–16:37") แสดงเป็นบล็อกความสูง 0 และอ่านยาก → ถ้า `end_at` ไม่มีหรือเท่ากับ `start_at` ให้ถือเป็น **จุดเวลา/เดดไลน์** แสดงเป็นธง + เวลาเดียว (ไม่แสดง "16:37–16:37") และบนตารางเวลาให้ความสูงขั้นต่ำเท่ากับ 30 นาทีเพื่อให้กดได้

6.3 **หน้า Review สับสนช่วงสัปดาห์:** ค่าเริ่มต้นแสดงสัปดาห์ที่แล้ว (26 ต.ค.–1 พ.ย.) แต่ส่วน "วางแผนสัปดาห์หน้า" แสดง 2–8 พ.ย. ซึ่งคือสัปดาห์ปัจจุบัน → แก้ให้ชัด: ค่าเริ่มต้นของหน้านี้ = **สัปดาห์ปัจจุบัน** (วันจันทร์–วันพุธแสดงหัวข้อ "สัปดาห์ที่แล้ว" เป็นแท็บแรก; วันพฤหัส–อาทิตย์เปิดสัปดาห์ปัจจุบัน) และ label ต้องระบุชัด "สัปดาห์นี้ / สัปดาห์ที่แล้ว / สัปดาห์หน้า" พร้อมช่วงวันที่ ส่วน "วางแผนสัปดาห์หน้า" ต้องเป็น **จันทร์ถัดจากสัปดาห์ที่กำลังรีวิวเสมอ**

6.4 **รายการวางแผนสัปดาห์หน้า** ใช้ไอคอนติ๊กเขียวเต็มทั้งที่ยังไม่เสร็จ (ดูเหมือนเสร็จแล้ว) → เปลี่ยนเป็นวงกลมว่าง (checkbox ที่กดแล้วเสร็จจริง) และงานที่เสร็จแล้วค่อยเป็นติ๊กเขียว

6.5 **ตัวเลขสถิติขัดกัน:** การ์ด "อัตราสำเร็จ 0% (0/1)" อยู่คู่กับ "งานที่เสร็จ 1" → ระบุนิยามให้ชัดใต้ตัวเลข (เช่น "งานที่ครบกำหนดในช่วงนี้ที่ทำเสร็จทันเวลา") และใช้นิยามเดียวกันทั้งหน้า Stats และ Review (ทำฟังก์ชันคำนวณเดียวที่ใช้ร่วมกัน + unit test)

6.6 **หน้าที่เนื้อหาเริ่มต้นไม่ตรงกัน** (Inbox, Matrix, Review, Stats เริ่มคนละตำแหน่ง เหลือพื้นที่ว่างซ้ายมาก) → ครอบด้วย `<PageContainer>` ตามหัวข้อ 2

6.7 **ปุ่ม "ย้อมสีตาม"** (ประเภท / เร่งด่วน / สำคัญ) ตัวเลือก "สำคัญ" ถูกเลือกอยู่แต่ไม่เห็นความต่างชัดเจนบน event → ตรวจว่าโหมดนี้เปลี่ยนสีพื้น event จริง และมี Legend ที่เปลี่ยนตามโหมด

6.8 **Event บนตารางเวลาที่ชื่อถูกตัด** (เช่น "8:30 - 9:00 ข้อ…", "9:0…") → ถ้าบล็อกเตี้ยกว่า 40px แสดงเวลาและชื่อในบรรทัดเดียว (`09:00 ชื่องาน`) และมี tooltip/popover แสดงรายละเอียดเมื่อ hover/กด

## 7. ลำดับการทำงาน (ทำตามลำดับ — commit แยกต่อ Step)

### Step 1 — Foundation: Tokens + Layout + Clean-up

งาน: นำ Design Tokens (หัวข้อ 2) มาใช้ทั้งแอป, ฟอนต์ไทย, `<PageContainer>`, ปรับสี event ให้เป็นพาสเทลตามประเภท, แทนที่ `!!`/`★` ด้วยชิป (หัวข้อ 3), จัดระเบียบ sidebar (4.2), แก้บั๊ก 6.1–6.8
**AC:**

- ทุกหน้าเนื้อหาจัดกึ่งกลางกว้างเท่ากัน ไม่มีหน้าไหนเหลือที่ว่างซ้ายแบบเดิม
- ไม่มีสีฟ้าเริ่มต้นของ FullCalendar เหลืออยู่ event ทุกอันเป็นสีตามประเภท ผ่าน contrast AA (ตรวจด้วย axe/Lighthouse)
- ไม่มีสัญลักษณ์ `!!`/`★` เหลือในหน้าใด
- บั๊ก 6.1–6.8 แก้ครบ มี test สำหรับสูตรสถิติ (6.5) และการแสดงงาน start=end (6.2)
- Lighthouse Accessibility ≥ 90

### Step 2 — Today Cockpit + Load Bar

งาน: หน้า "วันนี้" (5.1), ฟังก์ชันคะแนน + Next up (5.5 ส่วนแรก), ฟังก์ชันคำนวณภาระงาน (5.3) พร้อม migration `work_start/work_end/work_days` และหน้า Settings, Dobby Insight Bar แบบ dynamic, Progress ring, Timeline มีเส้น "ตอนนี้"
**AC:**

- เปิดเว็บแล้วเข้าหน้า "วันนี้" ก่อน เห็นข้อความ Insight ที่เปลี่ยนตามข้อมูลจริง (ทดสอบ 4 สถานการณ์: ไม่มีงาน / โหลดเบา / โหลดเกิน / มีเดดไลน์ใกล้)
- การ์ด Next up เลือกงานถูกต้องตามคะแนน, ปุ่ม "เริ่มโฟกัส" เปิด Focus Timer ผูกกับงาน
- สูตร load และ score มี unit test ครอบคลุมกรณีขอบ (ไม่มี estimate, วันหยุด, นัดทับ, งานเสร็จแล้ว)
- เส้น "ตอนนี้" เลื่อนตามเวลา Asia/Bangkok

### Step 3 — Week Planner + Task Tray + Time Blocking

งาน: มุมมองสัปดาห์แบบการ์ดต่อวัน พร้อม Load bar ที่หัวคอลัมน์ (5.2, 5.3), ถาดงานยังไม่มีเวลา, ลากวางลงวัน/ช่องเวลา, ธงเดดไลน์, มุมมอง time grid/เดือน/รายการเดิมยังใช้ได้, มือถือใช้ agenda แนวตั้ง
**AC:**

- ลากงานจากถาดไปวางที่วัน/ช่องเวลาแล้วบันทึกถูกต้อง ความยาวบล็อกเท่า estimate
- เปลี่ยนวันของงานแล้ว Load bar ของวันต้นทาง/ปลายทางอัปเดตทันที
- งานที่มีเดดไลน์แสดงธงที่วันเดดไลน์
- ใช้งานบนมือถือ (viewport 375px) ได้ครบ ไม่มี horizontal scroll ของทั้งหน้า
- ไม่ทำลาย sync Google Calendar เดิม (ย้ายงานแล้ว event ใน Google ถูกอัปเดต)

### Step 4 — Smart Planning (จัดวันให้ที + แนะนำย้าย + พิธีเช้า/เย็น)

งาน: ปุ่ม "จัดวันให้ที" พร้อมพรีวิว (5.5), "แนะนำย้ายงาน" เมื่อวันโหลดเกิน (5.3), พิธีเช้า Top 3 และพิธีเย็น "ปิดวัน" (5.4), Quick Add พร้อมพรีวิวชิป (5.6)
**AC:**

- "จัดวันให้ที" ไม่บันทึกอะไรจนกว่าผู้ใช้กดยืนยัน, ไม่วางทับนัด, ไม่เกินชั่วโมงทำงาน, งานที่ไม่พอเวลาแยกกลุ่ม
- แนะนำย้ายงานไม่เสนอย้ายงานที่เดดไลน์วันนั้น และไม่ย้ายไปวันที่หลังเดดไลน์
- Top 3 เก็บและแสดงถูกต้องข้ามการรีเฟรช, พิธีเย็นเลื่อนงานค้างได้ทั้งรายตัวและทั้งหมด
- Quick Add ใช้ parser ตัวเดียวกับ LINE (มีเทสต์ยืนยันว่า import ไฟล์เดียวกัน) และพรีวิวตรงกับที่บันทึก

### Step 5 — Matrix DnD + Micro-interactions + Mobile polish

งาน: Matrix ลากวางจริง (5.7), แอนิเมชันเสร็จงาน/Dobby (5.8), bottom tab bar + FAB + bottom sheet บนมือถือ (4.3), skeleton/empty/error states ครบทุกหน้า, dark mode ครบทุก token
**AC:**

- ลากการ์ดใน Matrix แล้วค่า urgency/importance เปลี่ยนและบันทึกสำเร็จ (ทดสอบทั้งเมาส์และทัช)
- เปิด `prefers-reduced-motion` แล้วแอนิเมชันถูกปิด
- ผ่านการทดสอบมือถือ 375px / 768px / 1280px ทุกหน้า, Lighthouse mobile ≥ 90 (Performance และ Accessibility)
- Dark mode อ่านได้ชัดทุกหน้า ไม่มี token ที่ไม่ได้กำหนดค่า

## 8. สิ่งที่ห้ามทำ

- ห้ามลบหรือเขียน schema/ข้อมูลเดิมทับ — ทุกการเปลี่ยนฐานข้อมูลต้องเป็น migration ใหม่ที่ย้อนกลับได้ และข้อมูลงานเดิมต้องแสดงผลถูกต้องหลังอัปเกรด
- ห้ามบันทึกแผนอัตโนมัติโดยไม่ผ่านพรีวิวและการยืนยันของผู้ใช้
- ห้ามเพิ่ม dependency หนัก (ต้องรันบน Cloudflare Workers/Pages ฟรี) — ถ้าจำเป็นต้องเพิ่ม library DnD หรือกราฟ ให้เลือกตัวเล็ก tree-shakable และบันทึกเหตุผลใน `docs/DECISIONS.md`
- ห้ามใช้สีเป็นสัญญาณเดียว (ต้องมีข้อความ/ไอคอน/รูปทรงประกอบเสมอ เพื่อ accessibility)
- เมื่อ spec ข้อใดไม่ชัดหรือขัดกับโค้ดที่มีอยู่ ให้เลือกทางที่เรียบง่ายและเข้ากับโครงสร้างเดิม บันทึกใน `docs/DECISIONS.md` แล้วทำต่อ ไม่ต้องหยุดถาม ยกเว้นเรื่องที่ย้อนกลับไม่ได้

## 9. Definition of Done (ภาพรวม)

1. เปิดเว็บแล้วเห็น **"วันนี้ควรทำอะไร"** ทันที ไม่ใช่แค่ตารางเปล่า
2. ทุกวันในสัปดาห์บอก **ภาระงาน** ได้ในพริบตา และจัดวัน/ย้ายงานด้วยการลากได้
3. ผู้ใช้ **จัดวันให้ทั้งวัน** ได้ด้วยปุ่มเดียว พร้อมพรีวิวก่อนยืนยัน
4. หน้าตาเป็นหนึ่งเดียวทุกหน้า (tokens, ฟอนต์, layout) ใช้งานสะดวกบนมือถือ และผ่านเกณฑ์ accessibility
5. บั๊กที่ระบุในหัวข้อ 6 ถูกแก้ครบและมี test ป้องกันการเกิดซ้ำ
